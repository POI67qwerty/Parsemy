1. まず全体像

アプリは、ブラウザーの中で動くJavaScriptとHTML Canvasを中心に作られています。画面の操作を受け取り、オブジェクトの位置・形を更新し、線や面をキャンバスへ描きます。

画面・操作
ボタン、一覧、数値入力、ドラッグ、タッチを扱います。
3D風の計算
物体の座標をカメラから見た2D座標に変換します。
描画
面や輪郭を描き、手前の面に隠れる線を省きます。
アセット
建物・家具・街路物など、棚から置ける形を定義します。
大切な設計上の見方：「データを持つ」「形を計算する」「画面に描く」「ユーザー操作を処理する」は、できるだけ別のファイルに分けています。機能の場所を探すときは、この4つのどれかを考えると見つけやすくなります。

2. 起動から表示まで

  1. index.html が画面の土台、キャンバス、ボタン類を用意します。
  2. style.css と studio.css が見た目を整えます。
  3. JavaScriptが決めた順番で読み込まれます。共通状態や計算関数が先に必要なので、順序を入れ替えると動かないことがあります。
  4. ユーザー操作でシーンのデータが変わり、UI更新と描画が呼ばれます。
  5. 書き出し操作では、現在の絵を画像として出力したり、シーン情報を保存・読み込みしたりします。
HTML / CSS（画面）
   ↓
engine-lib → engine-core → gizmo / render / input / io
   ↓
asset.js → asset-kit → asset-kit-assets → asset-controller
   ↓
studio-lib → floorplan / canvas-controls / studio-ui

実際のロード順と取り込み方法の正本は build-city-grid.py と index.html です。この図は役割を理解するための概略図です。

style.css
studio.css		基本の見た目とスタジオ画面の見た目。色、余白、レイアウト、選択状態などを管理します。形状計算や保存処理は担当しません。

engine-input.jsマウス・ペン・タッチ・ホイール入力、ドラッグ、パン、ズーム、消しゴムなどを扱います。操作感の不具合はここから追い、必要に応じて描画処理との接続を確認します。
engine-io.js画像書き出し、参考画像、保存・読み込み、ロックや起動時の接続など、入出力と初期化を担当します。
asset.js個別アセットの形・線・寸法の扱いを持つカタログ。既存アセットの形を直接直すとき、正規化や線の生成方法を調べる場所です。
asset-kit.js再利用できるアセット生成道具箱。同じ形状定義から線や面などの表現を作る共通機能を提供します。
asset-kit-parts.js複数のアセットで使い回す部品の定義。小物の共通形状や構成要素をまとめます。
asset-kit-assets.jsキット方式で定義されたアセットのデータ。形状の宣言と初期値をまとめて扱います。
asset-controller.jsアセットをシーンに追加する、既定値を適用する、棚に並べる、選択・配置を制御する層です。
studio-lib.jsスタジオUIと間取り機能で共有する関数や要素への接続をまとめます。複数画面で同じ道具を使うための橋渡しです。
studio-floorplan.js間取り・正投影モードの選択、移動、回転、寸法編集など。床面図上の操作を追う場所です。
studio-canvas-controls.jsキャンバス上のアセット操作と数値コントロールをつなぐ共通接続層。各アセット固有の寸法規則を勝手に置き換えず、既存の処理へつなぎます。
studio-ui.js画面UI全体の司令塔。アセット棚、シーン一覧、選択・グループ、数値パネル、プリセット、初期化などの操作をつなぎます。
build-city-grid.pyソースHTML・CSS・JavaScriptをまとめて配布用の単体HTMLを作るビルドスクリプトです。ソースを直接編集する場所ではありません。
build-guide.py以前のMarkdown解説をHTMLに変換するための補助スクリプトです。現在の解説書はこのファイルに依存せず、CODE_GUIDE.html 単体で読めます。
build.sh構文チェックとビルドをまとめて実行するシェルスクリプトです。実行後に生成される配布HTMLはビルド成果物です。
check-all-assets.js登録アセットが壊れていないかをブラウザー上で点検する検査コードです。形・線・操作の最低限の異常をまとめて見つけます。
tests/個別機能の回帰テスト群。隠線、ズーム、選択、アセット形状、書き出しなどを小さなシナリオで確認します。テスト名が調べたい機能の入口になります。
vendor/外部ライブラリのライセンス等を置く場所。ライセンス表示を残し、外部コードの利用条件を確認します。

4. アセット（置ける物）の追加・変更を読む

アセットは「棚に出す登録情報」と「形を作る処理」に分かれます。既存アセットの値を直すだけか、新しい形を作るかで調べる範囲が変わります。

  1. 棚に出る名前・分類・初期サイズ：asset.js の登録情報を確認。
  2. 共通部品から形を組む：asset-kit-parts.js の部品定義、asset-kit.js の組立道具、asset-kit-assets.js のアセット宣言を見る。
  3. 配置・選択・追加の挙動：asset-controller.js を確認。
  4. 線の見え方や面・隠線：アセットの生成元に加えて engine-render.js を調べる。
  5. 画面上の専用操作：engine-gizmo.js、studio-canvas-controls.js、studio-ui.js を追う。
性能表現に注意：関数やジオメトリを共通化することと、GPUの実インスタンシングは別の技術です。コードが実際にインスタンシングを使っていると確認できない限り、「GPU負荷が下がった」とは言えません。

5. アセットスクリプトキットを詳しく

asset-kit.js は、アセットの立体を組み立てるための独自ライブラリです。アセットごとに「線を作る処理」と「塗り・隠線判定に使う面」を別々に実装すると、両者の形がずれることがあります。キットでは同じ部品定義から線と三角形の面を導き、ずれにくくします。

一言でいうと：アセット定義は「部品をどう置くか」を返す。キットがそれを線画・面・範囲情報へ変換し、登録処理がアプリ本体につなぐ。

5-1. 4つの関連ファイルの役割

ファイル担当
asset-kit.js形状API本体。道筋、押し出し、円柱、繰り返し、回転体、部品登録、線と面の変換などを実装。
asset-kit-parts.js再利用可能な部品カタログ。窓・扉・ベンチなどを登録し、個々のアセットから呼び出せるようにする。
asset-kit-assets.jsキットを利用するアセット定義。アセット名・初期値・操作項目と、部品を組み立てる関数を登録。
asset.js / asset-controller.js従来アセットのカタログ・線画登録、および棚への配置などのアプリ接続。キット定義はこの登録経路へ統合される。

5-2. アセット定義の基本形

ASSET_KIT.define("simpleBench", {
  label: "ベンチ", glyph: "▰", group: "street",
  w: 1.6, d: 0.42, h: 0.45, accent: "#9b7654",
  controls: []
}, (o, K) => {
  const width = Math.abs(2 * o.ra);
  const depth = Math.abs(2 * o.rb);
  const height = Math.abs(o.h);
  return [
    K.box(K.rectPath(width, depth), height - 0.05, height),
    K.box(K.rectPath(0.06, 0.06, -width * 0.4), 0, height - 0.05),
    K.box(K.rectPath(0.06, 0.06,  width * 0.4), 0, height - 0.05)
  ];
});
  • kind は内部ID。英数字の一意な名前にします。
  • meta は棚表示名 label、アイコン glyph、分類 group、初期幅・奥行き・高さ、色 accent、固有初期値、編集項目 controls など。
  • (o, K) => parts は形状ビルダー。o はシーン内の現在のアセット設定、K はキットAPI。戻り値は部品オブジェクトの配列。
  • 通常は ASSET_KIT.define がアセット登録と線生成を接続します。既存IDを上書きする特別な場合は opts.replace の有無、線の置換設定を実装と合わせて慎重に確認します。

5-3. 座標の約束

部品の座標はアセット中心のローカル座標です。X＝左右、Y＝奥行き、Z＝高さ（上がプラス）。長さの単位はメートルです。アセット全体の位置・回転・拡大・接着面への追従は、エンジン側の座標変換 L2W() が行います。ビルダー内でワールド座標に変換しないでください。

標準の部品は正面を -Y 側に置く約束です。前面パネルを作るときの axis:"y" は、2D輪郭をX-Z平面上に置いてY方向へ押し出す意味です。

5-4. よく使うAPI

API用途・考え方
K.rectPath(w,d,cx,cy)幅・奥行き・中心位置を指定して2D四角形の頂点列を作る。これ自体はまだ立体ではありません。
K.circlePath(r,n,cx,cy)円をn角形の頂点列として表現。線画は多角形の分割数に応じた折れ線になります。
K.roundRectPath(w,d,r,seg)角丸長方形の輪郭。丸み0なら四角形に戻ります。
K.box(path,start,end,opts)輪郭を指定軸に押し出して立体化。名前は箱ですが、任意の多角形も押し出せます。実装の中心は extrude。
axis:"z"既定値。輪郭をX-Y平面に置き、高さ方向Zへ押し出す。柱・箱など。
axis:"y"輪郭をX-Z平面に置き、前後Y方向へ押し出す。正面板、壁、窓枠など。
axis:"x"輪郭をY-Z平面に置き、左右X方向へ押し出す。
holes:[path]押し出す輪郭の穴を指定。holeSides:true なら穴の内壁も立体として作ります。
K.sheet(path,a,b,opts)薄い板やシートを表す。用途によって側面・端の線を抑えるオプションを使います。
K.cylinder(r,a,b,{axis,seg})円柱を作る。軸・円周分割数を指定でき、細い棒やノブなどに使う。
K.revolution(profile,opts)半径と高さの断面を回転して、鉢・球・円錐など回転対称形を作る。
K.loft(rings,opts)複数の断面輪郭をつないで立体化。断面ごとに幅や位置が変わる形に使う。
K.face3(points,opts)3D点で定義する自由な面。傾いた板など通常の押し出しで表しにくい形向け。
K.moveParts(parts,dx,dy,dz)部品群をローカル座標で平行移動。部品を作ってから置き位置を調整する。
K.repeat(n,fn) / K.grid(rows,cols,fn)同形状を規則的に繰り返す。窓の桟・階段・商品列などをループで生成。
K.repeatParts(parts,opts)部品一式を指定方向と間隔で複製。位置だけでなく、角の線選別用マークも複製ごとに分ける。
K.param(o,key,fallback)編集値を読む共通関数。現在のオブジェクト値を優先し、なければアセット定義値、コントロール既定値、最後にfallbackを使う。
K.registerPart(name,build) / K.part(name,opts)部品カタログへ形を登録し、寸法や位置などの引数で呼び出す。

5-5. 部品カタログを使う

asset-kit-parts.js は形そのものを登録します。例えば窓部品は、外枠に穴を開け、必要なら穴へガラスと縦桟を加えます。扉部品は枠・扉板・取っ手をまとめます。部品を使う側は、細かな三角形を毎回作らず、サイズや位置を渡します。

// 部品カタログへの登録例（概念例）
K.registerPart("panel", (o) => {
  const path = K.rectPath(o.w, o.h);
  return [K.box(path, -o.t/2, o.t/2, {axis:"y"})];
});

// アセット側ではサイズと配置を指定して呼ぶ
const panelParts = K.part("panel", {
  w: 0.8, h: 0.5, t: 0.04, at: [0, 0, 1.2]
});

部品は通常、原点中心で正面を -Y に向けます。at:[x,y,z] は配置位置。部品カタログ内では既定値や安全な最小寸法を設け、ゼロや負値でも破綻しないか確認してください。

5-6. 編集項目（controls）と形状の連動

meta.controls はUIに出す編集値の定義です。キー、表示名、初期値、最小・最大、刻み、単位、ハンドル情報などを指定するものがあります。形状ビルダーも同じキーを読み、UIで値を変えた時に実際の形が変わるようにします。

controls: [{
  key: "seatThickness",
  label: "座面の厚さ",
  type: "range",
  default: 0.05,
  min: 0.01,
  max: 0.2,
  step: 0.005,
  unit: "m"
}]

// ビルダーでは編集値を同じキーで読む
const t = Math.max(0.01, K.param(o, "seatThickness", 0.05));

キー名の不一致は「UIは動くのに形が変わらない」原因になります。初期値、保存・読み込み、複製後の独立性、最小値と形の重なりもテストします。

5-7. キット内部で線と面になるまで

  1. define(kind,meta,build) がアセットを登録し、形状ビルダーを呼べるようにする。
  2. ビルダーが返したpartsを partEdges() が頂点のつながり（稜線）へ変換。線画側はその線を既存の描画系へ渡す。
  3. partTris() が部品を三角形の集合へ分解。穴や断面を考慮した面が、深度・隠線判定に使われる。
  4. ローカル頂点を L2W() でワールド位置へ変換する。
  5. 選択範囲用の点、描画線、面が同じ部品定義を起点に得られるため、形の不一致を減らせる。

ただし、幾何を共通定義にしただけで描画負荷が必ず下がるわけではありません。実際の性能は生成回数、線・三角形数、キャッシュの有無、ブラウザー計測で判断します。

5-8. 追加時のチェックリスト

  • kindが重複していないか。棚のlabel・分類・初期寸法・色が妥当か。
  • ローカル座標の正面（-Y）と高さ（+Z）が意図どおりか。
  • 幅・奥行き・高さを極端に小さくしてもゼロ面やNaNが出ないか。
  • 線画と塗り面が一致し、穴・内壁・裏面が正しく見えるか。
  • 正面・側面・上面・透視など複数の投影で、隠線と輪郭を確認。
  • 選択範囲が形に合うか。回転・移動・寸法ハンドルが使えるか。
  • 保存・読込・複製・JSON入出力で固有値が保たれるか。
  • 既存アセットを置き換える場合、従来の見た目と編集仕様を比較するテストを追加。
補足：この章はキットの設計と代表APIの読み方をまとめた案内です。APIの完全な引数・例外・実装仕様は asset-kit.js および asset-kit-parts.js が正本です。

8. 変更するときのおすすめ手順

  1. 症状を分ける：画面表示、形状、操作、保存、速度のどれかを特定。
  2. 担当ファイルを探す：上のファイル表から入口を選び、呼び出し元・呼び出し先も追う。
  3. 既存の類似機能を確認：同じ処理を二重に足さず、既存の正規ルートに合わせる。
  4. 変更範囲に合うテストを実行：tests/run.sh の使い方は下記を参照。
  5. 構文・ビルドを確認：プロジェクトのルートで bash build.sh。
  6. 結果を正確に報告：成功した検査、失敗した検査、未計測の性能を分けて記録。
# 構文チェック・配布用HTML生成
bash build.sh

# 個別ブラウザーテスト
bash tests/run.sh tests/fast-interaction-preview.js
bash tests/run.sh tests/scene-parent-hierarchy.js

# 全アセット点検（環境準備が必要な場合あり）
bash tests/run.sh check-all-assets.js

テスト名は tests/ の実ファイル名に合わせます。実行前に各スクリプトの先頭や tests/run.sh を見ると、引数や環境要件を確認できます。

注意：生成された配布HTMLはソースではありません。修正は元の .js・.css・index.html に行い、必要なときにビルドし直します。生成ファイルを直接編集すると、次のビルドで変更が消えることがあります。
City Grid Studio 開発ガイド — ファイルの役割を理解するための案内です。関数名や読み込み順などの細部は、各ソースファイルを正本として確認してください。
