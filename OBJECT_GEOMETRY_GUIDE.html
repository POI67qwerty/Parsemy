大事な性質：線も面も 保存されているのは「数値（o）」だけ。
形は毎回 o から作り直されます。だから寸法を1つ変えると、

ポイント：lines* 関数は ローカル座標（x=幅／y=奥行き／z=高さ）だけを扱い、 ワールドへの変換は L2W()（＝pt()）が一手に引き受けます。 だから回転・移動・接着を足しても、形の式は書き換えずに済みます。

2. 座標系（形を決める土台）

2.1 ワールド座標は X=右／Y=上／Z=奥

このアプリのワールドは Y が上 です（数学の教科書と同じ右手系）。

軸向きUI 上の呼び方
X右左右（赤）
Y上上下（青）※ギズモ表示名は Z
Z奥（手前が −Z）手前奥（緑）※ギズモ表示名は Y

用語：ギズモの表示名は「上下＝Z／手前奥＝Y」に統一していますが、 内部のワールド座標は上表のままです（P.cx / P.ch / P.cz も従来どおり）。 表示名と内部名が違うのは 既存の保存データを壊さないためです。

面の向きは k で表します。PL[k] が「その面のなかの2軸」を返します。 

const PL = { 0: [2, 1], 1: [0, 2], 2: [0, 1] };
//        k=0 → 面内は Z と Y（左右を向いた面）
//        k=1 → 面内は X と Z（地面に平行な面）★ アセットの標準
//        k=2 → 面内は X と Y（手前を向いた面）

アセットはほぼ全部 k=1, d=−1 で作られます。これは
「地面に平行な面（幅×奥行き）を、上へ押し出す」という意味です。

2.3 L2W：ローカル座標 → ワールド座標

すべての形は、最後にこの1本を通ります。 

function L2W(o, x, y, z) {
    const [iu, iv] = PL[o.k];          // 面内の2軸（k=1 なら iu=0(X), iv=2(Z)）
    const cs = Math.cos(o.rot * DG),   // DG = π/180
          sn = Math.sin(o.rot * DG);
    const v = [0, 0, 0];
    v[o.k] = o.d - o.d * o.lift - o.d * z;      // ① 法線方向（＝高さ）
    v[iu]  = o.ca + x * cs - y * sn;            // ② 面内の横（回転つき）
    v[iv]  = o.cb + x * sn + y * cs;            // ③ 面内の縦（回転つき）
    const f = o.off || [0, 0, 0];
    return [v[0] + f[0], v[1] + f[1], v[2] + f[2]];
}

パーツの外側の回転（spin / spinPivot）— 結合体を回すため

k = 0 / k = 2（縦の面）は rot が「面の中の回転」になるため、**上下軸まわりの回転（ヨー）を
表せません**。そこで座標変換の一番外側に、面の向きに依存しないヨーを持たせています。

項目内容
spinワールド上下軸まわりの角度（度）
spinPivotその回転中心（ワールド座標 [x,y,z]）
function applyPartSpin(o, v) {              // 1点 v にヨーを掛ける
    const d = o.spin, p = o.spinPivot;
    if (!d || !p) return v;
    const a = d * DG, cs = Math.cos(a), sn = Math.sin(a),
          dx = v[0] - p[0], dz = v[2] - p[2];
    return [p[0] + dx * cs + dz * sn, v[1], p[2] - dx * sn + dz * cs];
}

掛ける順番は 面の中（rot）→ 平行移動（off）→ spin → 傾き（rotX/rotZ）。
ただし rot と spin は＋の向きが逆（rot は (x,z) 平面で＋が反時計、spin は＋が時計）。
結合体を回すときは k=1 のパーツの rot から角度を引くことで向きをそろえている
（そろえないと「中心は時計回り・形だけ反時計回り」になり、角の点が最大1.0mずれる。§5V-4）。
l2wRaw()・genShape() の点の式・L2W() の壁沿い基底の分岐が同じ順番なので、
線画・面・当たり判定・ハンドルがそろって回ります。
translateDefinition() は形と spinPivot を同じ量だけ動かすので、移動しても軸がずれません。

結合体を回すときは、全パーツが同じ spinPivot を共有するので剛体として回ります
（rotateCompoundBy()／spinComposePivot() は CITY_GRID_STUDIO.md §5V）。

傾き（rotX / rotZ）— 画面の回転リングで作る角度

上下（ワールドY）まわりの回転は従来どおり rot（画面上の回転）ですが、
左右（ワールドX）・手前奥（ワールドZ）まわりの回転は rotX / rotZ として持ちます。 

function objectTiltMatrix(o) {
    const ax = (o.rotX || 0)·DG,  az = (o.rotZ || 0)·DG;
    if (!ax && !az) return null;              // 傾いていなければ何もしない（今までと同じ）
    // R = Rz(az) · Rx(ax)
    return [
        [ cz, -sz·cx,  sz·sx],
        [ sz,  cz·cx, -cz·sx],
        [  0,     sx,     cx],
    ];
}
// ローカル原点を中心に回す（中心は「高さの真ん中」＝ l2wRaw(o,0,0,h/2)）
P' = center + M · (P − center)

L2W の最後でこの回転を掛けるので、線画・面の三角形・当たり判定・ハンドルが
すべて同じだけ傾きます。rot（上下）と rotX/rotZ（左右・手前奥）は独立に足せます。

ポイント：傾きの中心を「底面」ではなく「高さの真ん中」にしています。 底面を中心にすると、傾けたときに下の角が地面へ潜り込んで「倒れた」ように見えるためです。 回転角は画面のリングを掴んで決め、15°刻みでスナップ（Shiftで自由）します。

k=1, d=−1 を代入すると、こうなります（アセットの標準形）。 

ワールドX = ca + x·cosθ − y·sinθ
ワールドY = −1 + lift + z          ← 高さ
ワールドZ = cb + x·sinθ + y·cosθ

つまり z はそのまま上へ（−d·z = +z）、x/y は回転行列で90°回るだけ。

計算：v[k] = d − d·lift − d·z の −d·z がポイント。 d が負（＝面が手前向き）だと −d = +1 になり、z は上向きに伸びます。 d が正のオブジェクト（奥向きの面）では上下が反転するので、アセットは必ず d=−1 で作ります。

2.4 例外：壁に沿うパーツ（wallSideBasis）

横壁看板のように「建物の横壁に貼り付く」パーツは、水平面＋高さの式では表せません。
そこで親の姿勢から 正規直交基底（origin / u / v / n）を作り、そこへ載せます。 

ワールド = origin + u·x + v·y + n·z      （n = 壁の外向き法線）

基底は syncAttachedPart() が親の移動・回転・寸法変更のたびに更新します。
だから親を回しても看板は壁に貼り付いたまま動きます。

2.5 積層建物の customPt も L2W に統一

積層建物（縁付き・ベベル・凹窓）は寸法を floors[] に持ち、線画を
「x=幅／y=奥行き／z=高さ」のローカル座標で組み立てます。その変換が customPt です。 

const customPt = (o, x, y, z) => L2W(o, x, y, z);

以前は独自の式（回転 rot だけを掛ける）だったため、**生成面（k）を X／Z にしても
積層建物だけ向きが変わらない・傾けても傾かない**という差が出ていました。
k=1, rot=0 のとき両者は完全に同じ結果なので、既存データの見た目は変わりません。

3. カメラと投影（3Dを画面にする計算）

3.1 cam()：視点の回転3段

ワールドのベクトルを、カメラ座標へ移します。順番は 水平回転 → 上下 → ロール。 

x1 =  v[0]·cos(yaw) + v[2]·sin(yaw)
z1 = -v[0]·sin(yaw) + v[2]·cos(yaw)      // ← yaw は Y 軸まわり

y2 =  v[1]·cos(pitch) - z1·sin(pitch)
z2 =  v[1]·sin(pitch) + z1·cos(pitch)    // ← pitch は X 軸まわり

→ ロール（魚眼モードのみ）を掛けて [x, y, z] を返す

カメラの位置は camPos() = [P.cx, P.ch − 1, P.cz]、逆向きの移動は CO() = [−cx, 1−ch, −cz]。
3D点を投影するときは 点 + CO()（カメラからの相対位置）にしてから cam() へ入れます。

3.2 scr()：透視投影

const q = cam(v);
if (q[2] <= 0.02) return { ok:false };      // カメラの後ろ／真横は描かない
const f = (W * P.lens) / 36;                // 焦点距離（36mm センサー基準）
x = W/2 + (f * q[0]) / q[2];
y = (H * P.hz) / 100 - (f * q[1]) / q[2];   // hz は水平線の高さ（%）

P.lens を大きくすると望遠（画角が狭い）、小さくすると広角。
hz は「地平線を画面のどこに置くか」で、アイレベル表現に効きます。

3.3 正投影（前・横・上のビュー）

間取り編集の3ビューは透視ではなく 正投影（平行投影）です。
基底だけを差し替えて、同じ処理で3方向を出します。

ビューright（画面右）up（画面上）depth（奥行き）
正面XYZ
真横ZY−X
真上XZ−Y
sc = orthScale();                       // 通常は min(W,H)/7.2（1mあたりのpx）
x = ax + dot(v, right) * sc;
y = ay - dot(v, up) * sc;
depth = dot(v, depth);                  // 隠れ線の判定用

正投影は 距離で大きさが変わらないので、寸法の読み取りと編集に向いています。
3D との差が出ないように、正投影でも同じ L2W の点を使っています。

3.4 scr3 と CO：3Dの点を線にする

const scr3 = (p) => (orthView ? scr(p) : scr(V.nrm(p)));
  • 正投影 … 点そのものを投影（平行投影なので位置が意味を持つ）
  • 透視 … カメラからの 向きベクトルに正規化してから投影

線の点列は「カメラからの向き」で持っているので、視点を回すと線が追従します。

3.5 dens3：点の間を球面で埋める

2点の間を、角度で細かく分割して補間します（0.004 rad 刻み）。 

n = ceil( acos( dot(nrm(u + CO), nrm(v + CO)) ) / 0.004 )

直線を「大円」として扱うので、魚眼（5点・6点透視）でも線が曲がって正しく見えます。
正投影ビューでは投影が線形なので、この補間は省いて高速化しています。

4. genShape：基本図形の作り方

アセット以外の素の図形（四角・円・直方体・円柱…）は engine-core.js の genShape(o) が作ります。
asset.js は genShape を 包み直して、type === "asset" だけ genAsset() へ振り分けます。 

genShape = (o) => o?.type === "asset" ? genAsset(o) : baseGenShape(o);

4.1 面内座標 → 押し出し

const [iu, iv] = PL[k];
const q = (a, b, ee = 0) => {
    v[k]  = d - d*lift + ee;               // ee = 押し出し量
    v[iu] = ca + (a-ca)*cs - (b-cb)*sn;    // 中心まわりに rot 回転
    v[iv] = cb + (a-ca)*sn + (b-cb)*cs;
};
const e = -d * h;                          // 押し出し量（h は高さ）

h を押し出すと k 方向へ e = −d·h 伸びます。d=−1 なら上へ +h。

4.2 box の隠れ線判定

直方体は 8頂点・6面・12辺を作り、見えている面に属する辺だけを残します。 

vis[f] = dot(法線, 面の中心 → カメラ) < 0
辺は「両隣の面のどちらかが見えていれば」描く

法線の向きは、面の中心が箱の中心より外を向くように反転させてから判定します
（巻き方向に依存しないため）。ob.wf（ワイヤーフレーム）が真なら全辺を描きます。

ベベル輪郭の式（beveledBoxFootprint）

4隅の中心を内側へ b だけ寄せ、そこを半径 b の円弧で結びます。 

角の中心： (±(hw−b), ±(hd−b))     hw=w/2, hd=d/2
点：      中心 + b·(cosθ, sinθ)    θ を90°ずつ、各角を segments 分割

segments=1 なら「1枚の平面で面取り（＝隅切り）」、segments=4 なら丸みのあるベベル。
b=0 なら普通の長方形の4点に戻ります。

ベベルの面は線にしない（2026-11-02、依頼28-②で確定）： 面取りの弧の上にある縦の稜線は bevelEdgeKind(index, offset, segments) が 2 を返すので描きません。角ごとに残る1本（1）は line.seam = 1 を付けておき、 面ONのときは描きません（線だけ表示では形が読めるように描きます）。 弧の両端だけ残す旧ルールでは、角をはさむ平行な2本が「二重線」に見え、 角ごとに1本残す案では「いちばん手前の角にだけ縦線が1本」になっていました。 凹窓階層建物（弧の上の縦線を描かない）と同じ扱いに揃えています。 ベベル階層建物は 169 → 73 → 0本（線だけ表示では32本）、 ベベル直方体（押し出し2m）は 22 → 10 → 0本（線だけ表示では4本）。

ポイント：この1つの輪郭点列を、線画・面の三角形・外接範囲が共有します。 だから「見た目の角」と「当たり判定の角」が食い違いません。

折れ線オフセット（offsetPolyline2D）

屋根の板厚を作るときに使う計算です。
各線分を法線 n = (dz, −dx)/|…| 方向へ dist ずらし、
隣り合う直線の 交点 を新しい折れ点にします（マイター）。 

交点 t = cross(P_i − P_{i−1}, dir_i) / cross(dir_{i−1}, dir_i)

平行（cross ≈ 0）のときは点をそのまま使うので、0除算になりません。

6.2 1個ずつの計算

box（直方体）— すべての基準

w = 2ra, d = 2rb
底面4隅 (x=±w/2, y=±d/2, z=0) ／ 上面4隅（同じで z=h）
→ boxA() が 底面・上面・4本の縦辺 = 6本の線
→ 面は 6面 × 2三角形 = 12三角形

beveledBox（ベベル直方体）

輪郭 = beveledBoxFootprint(w, d, bevelOffset, bevelSegments)   // 4隅を円弧で面取り
z0=0, z1=h に同じ輪郭を置き、対応する頂点を縦辺で結ぶ
h=0（未押し出し）なら 1本の平面ポリゴンだけ

bevelOffset の上限は min(w,d)/2 − 0.001（＝角が消えて丸にならない限界）。

cornerCutBox（隅切り直方体）

5角形の輪郭：(-hw+b, -hd) → (hw, -hd) → (hw, hd) → (-hw, hd) → (-hw, -hd+b)
切り口の辺と、切り口側の2本の縦辺だけ赤（cutColor）
開口ON：切り口の中央を基準に 幅 openingW・高さ openingH・奥行き openingDepth の
        空洞を、切り口の法線（inward）方向へ掘る

inward は「切り口の接線を90°回した向き」のうち、
重心の側を向くほうを選びます（＝必ず内側へ掘れる）。
奥行きの上限は cornerCutOpeningRayDistance() = 切り口の中央から内側へ向かう光線が
反対側の辺に当たるまでの距離 − 0.025 m。

sign（看板）・wallSign（壁付け看板）

看板：外枠 = boxA(w, d, 0.08h, 0.82h)
      絵枠 = faceW × faceH の四角を board の手前 y へ（±fy ぶん浮かす）
壁付け看板：板の輪郭（幅×高さ）を厚み方向へ押し出した箱
      ベベルON なら wallSignFacePoints() = beveledBoxFootprint(幅, 高さ, offset, seg)
      金具 = 板の左側面（−x）から bracketLength だけ横へ伸びる直方体を 0〜3本
             高さは z = 高さ·(i+1)/(本数+1) − 高さ/2（中心基準で均等）

wallSideSign（横壁看板）

親の横壁に沿う基底 wallSideBasis を使うため、L2W が通常の k 式ではなく
origin + u·x + v·y + n·z になります（§2.4）。
板は縦×横×厚み、金具は板の裏（壁側）から出る直方体で、本数は 0〜3。

awning（店舗テント）

half = d/2, baseFrontY = -d/2
edgeY : -d/2 〜 +d/2−0.025（前縁の奥行き）
edgeZ : 0 〜 h          （前縁の高さ。0 まで下げると三角柱）
thickness = clamp(awningThickness, 0.03, 0.45h) 既定 max(0.05, 0.14h)
frontBottom / backBottom : 前後の下端（0〜edgeZ−0.03 / 0〜h−0.03）

描くのは 天板（前縁→後縁）・底板・前面・後面・左右の側面 の6枚。
初期値は edgeY=−d/2, edgeZ=h で、このとき天板が水平・前面が垂直になり 直方体。
店舗テント（単体）は 3×1×0.35（板厚 max(0.05, 0.14·0.35)=0.05）、
建物に付くテントは 3×1×1（板厚 max(0.04, 0.14·1)=0.14）で、
どちらも edgeZ=h から始まるので 最初から直方体です。
snapAwningEdge() が ±0.03 m で最大値・最小値へ吸着するので、
ハンドルを端まで動かすだけで必ず直方体（最大）か三角柱（最小・最奥）になります。
前縁のハンドルは 上下（高さ）と手前奥（奥行き）の2軸を持ち、
2軸目は1軸目と直交させてあります（真下へ引いたのに手前奥も動く、を防ぐため）。

balcony（壁付けベランダ）

床スラブ   = 箱(w, d, z 0 〜 t)
前面腰壁   = 箱(w, t, z t 〜 t+railH)                      手前 y = −d/2+t/2
左右腰壁   = 箱(t, d−t, z t 〜 t+railH)                    前面の腰壁の後ろ側から詰める
支持ブラケット = (x=±0.34w, 壁側) → (同じx, 手前, 0) の2本

壁側が +Y、張り出しが −Y。床と腰壁を 別の箱にしているので、
面編集で1枚を動かしても形が崩れません。左右の腰壁は前面の腰壁と角で重ならないように
前面の腰壁の後ろ側から詰めます（重ねると塗りが二重になって濃くなる）。

線画（linesBalcony）は、この3つの箱を1つの立体として描きます。
重ねた箱をそのまま描くと、角に二重線が出て、スラブと腰壁の境に継ぎ目の線が入り、
手前の面が奥の線を隠して線が途中で欠けるためです（2026-11-01）。

stall（屋台）

写真のような売店。コの字の壁（奥＋左右）の手前下へカウンター箱、
真上へ屋根箱を載せた形です。寸法はすべて stallGeometry(o) が唯一の出どころです。 

奥の壁   = 箱(w, t, z 0 〜 roofBottom)                    y = +d/2 − t/2
左右の壁 = 箱(t, d−t, z 0 〜 roofBottom)                  y = 0（奥の壁の手前まで）
カウンター = 箱(w, cd, z 0 〜 ch)                         y = −d/2 − cd/2 （奥の面がコの字に密着）
屋根     = 箱(w, d + ro, z roofBottom 〜 h)               y = −ro/2（手前へ ro だけ張り出す）

t   = stallWallThickness   既定 w·0.0375
ch  = stallCounterHeight   既定 h·0.44     ← 下の面（床）は動かさない
cd  = stallCounterDepth    既定 d·0.34     ← 奥の面はコの字に付いたまま、手前の面だけ動く
rt  = stallRoofThickness   既定 h·0.09     ← 上の面（= h）は動かさない、下の面だけ動く
ro  = stallRoofOverhang    既定 d·0.24     ← 手前の面だけ動く
roofBottom = h − rt
  • 全体の幅・奥行き・高さは通常の寸法ハンドル（ra / rb / h）。
    カウンターの幅・屋根の幅は w に、屋根の奥行きは d + ro に追従します。
  • 高さを変えても屋根の厚さは比率で自動追従しません（rt は絶対値）。
    ただし stallRoofThickness を未設定（0）にすると既定値 h·0.09 に戻ります。
  • カウンターの高さは roofBottom − 0.12 を上限にしています（屋根の下面へめり込ませないため）。

stool（丸椅子）

座面・ポール（脚）・台座の3つの円柱。屋台のカウンター（高さ約1.05 m）に合わせた初期値です。
半径はどれも正円（ra と rb を別々には使わない＝楕円にならない）。 

台座   = 円柱(半径 g.baseR, z 0 〜 g.baseH)
ポール = 円柱(半径 g.legR,  z g.baseTop 〜 g.poleTop)
座面   = 円柱(半径 g.seatR, z g.seatBottom 〜 h)
g = stoolGeometry(o)   // engine-tools.js：寸法の唯一の計算元

stoolGeometry(o) が返す値（6つの寸法はすべてここから決まる）:

記号意味決め方既定値（0.36×0.36×0.45）
seatR座面の半径stoolSeatRadius（未設定なら min(w,d)/2）0.18
seatT座面の高さ（厚み）stoolSeatThickness（未設定なら h·0.13）0.0585
legRポールの半径stoolLegRadius（未設定なら min(w,d)·0.11）。min(seatR, baseR) を上限に clamp0.0396
legHポールの高さh − seatT − baseH（自動）0.3510
baseR台座の半径stoolBaseRadius（未設定なら min(w,d)·0.30）0.108
baseH台座の高さstoolBaseHeight（未設定なら h·0.09）0.0405
  • 幅・奥行きは座面の半径1つから決まります（ra = rb = seatR）。
    左右の面ハンドル（u+ / u-）は出しません（出すと座面だけ楕円になり、
    半径ハンドルの値と食い違うため）。
  • 全体の高さ h は通常の寸法ハンドル（上下の面）で編集できます。
  • 面（塗り）は3つの円柱を exportSurfaceTriangles の cylinder(r, z0, z1, n) で作ります。

stairs（階段）

n = clamp(steps, 2, 24)      既定 6
1段の奥行き sd = d/n 、1段の高さ sh = h/n
i 段目：踏面を z=(i+1)·sh に、蹴上げを y0 = -d/2 + i·sd に
断面は「手前から奥へ上がる」実際の階段形状

crosswalk（横断歩道）

n = clamp(stripes, 3, 16)    既定 7
gap = d/(n+1) 、白線の幅 stripeD = 0.6·gap
i 本目：y = -d/2 + gap·(i+1) 、z=0.012 に薄い四角

cylinder / cone / sphere

円柱：上下の楕円リング2本（n=12）。縦の稜線は描かない
円錐：底面リング（n=16）＋ 視点から見える左右2本の母線（角度 ph±90°）
球  ：緯度・経線を描かず「視点に正対する円」1本（48分割）。
      中心は L2W(o,0,0,h/2)、半径 r = min(w,d,h)/2

球の式はカメラの right/up をそのまま使うので、どの視点でも画面上で真円になります。

triPrism / triPyramid

三角柱：前後の三角形（y=∓d/2）＋ 対応頂点を結ぶ3本
三角錐：底面三角形（y=-d/2 から y=+d/2 の二等辺）＋ 頂点 (0,0,h) への3本

lantern（ランタン）

胴：z=0.22h 〜 0.7h の八角リング2本 ＋ 8本の縦骨
上の絞り：0.7h → 0.78h（半径 0.82 倍）＋吊り手 0.78h→0.94h→h
内側の帯：0.36h と 0.56h に半径1.02倍のリング（紙提灯の雰囲気）

person（人物）— 1つの骨格計算を全員で共有

personPose(o) が 関節の位置を返し、線画・面メッシュ・関節ギズモが同じ値を使います。 

身長 h、体格 bodyScale、肩幅 shoulderScale、頭 headScale、脚の開き legSpread
基本の高さ
  legTop = (0.47 − 0.16·crouch)·h
  torso0 = (0.44 − 0.16·crouch)·h   （腰）
  torso1 = (0.78 − 0.18·crouch)·h   （肩）
  head0/head1 = (0.84 / 0.99 − 0.18·crouch)·h
脚（回転しても長さが変わらない）
  hip → knee の向きを thighLen 倍、hip 角度ぶん回す
  knee → foot は、さらに −knee角度 ぶん回す
胴
  腰の支点 (0, torso0) のまわりに waistAngle だけ回す → 肩の面・首の根元が追従
頭
  首の根元から (waistAngle + neckAngle) 方向へ head0〜head1 を積む

角度の符号は「正で前に振る（−y 側）」、膝だけ「正で曲げる」。

building（開口のある建物）

w=2ra, d=2rb, h
openingW = clamp(openingW, 0.1, w−0.1)      既定 0.56w → 4m なら 2.24m
openingH = clamp(openingH, 0.1, h−0.1)      既定 0.66h → 5m なら 3.3m
backY    = clamp(openingBack, −d/2+0.025, d/2−0.025)   既定は奥の面（1.475m）

形は「外側の箱」と「内側の空洞」を 別々の輪郭として描きます。 

外枠の正面・背面の四角（w × h）
内側の開口枠（−ow/2〜+ow/2, 0〜oh）を正面・背面・奥パネルに
奥パネル（backY）が背面と一致しないときだけ、その四角も描く
左右の柱（幅 sideT=(w−ow)/2）と上梁（高さ topT=h−oh）は外枠との差で表現
窓グリッド（任意）は開口と重なる窓を省いて貼る（windowRectHitsOpening）

stackedBuilding / beveledStackedBuilding（縁付き階層建物）

floors[] の各階 f を下から順に描く
  本体 = addBox(f, w, d, z=0, h)        ※ z は f.z のオフセットで加算
  縁   = addBox(f, w+2·rimOverhang, d+2·rimOverhang, h−rimHeight, rimHeight)
         rimHeight 既定 0.16 / rimOverhang 既定 0.18
  開口 = 1F だけ（openingEnabled が真のとき）。openingW/H は stackedOpeningParams()
共有辺を二重に描かないよう、箱の12辺を1回ずつ描く（底面は最下階のみ、上面は縁が隠すため省略）
beveledStackedBuilding は同じ処理を beveledBoxFootprint で行う

recessedStackedBuilding（凹窓階層建物）

各階：z を積む（1F だけ firstFloorHeight = floorHeight + firstFloorExtra）
     階の間は floorGap（関数の既定 0.12／配置時の初期値 1.25）= 接合部の高さ = 窓の高さ
輪郭：beveledBoxFootprint の「正面右の角だけ」を cornerBevel（既定 0.45）で丸める
窓帯：外周の折れ線 outer と、内側へ windowDepth だけ入った inner の間の帯
      横壁側（+x）まで回り込むので、正面と横面の凹みがつながって見える
      mullion（縦の間柱）は外周の累積長を windowCount 等分した位置
蓋：階の上端（接合部）は窓の幅だけ切り欠いた多角形を作り、
     polygonEarClip で三角形分割する（重心分割だと凹みの外へはみ出す）

pathPipe（パスパイプ）

中心線 = 制御点を丸めた折れ線（角は円弧で置換）
各点でフレームを作る： tangent、reference（|tz|>0.92 なら Y 軸、他は Z 軸）、
                     side = tangent × reference 、 binormal = tangent × side
リング = center + side·r·cosθ + binormal·r·sinθ（sides 既定 10）
側面 = 隣り合うリングの四角を2三角形へ。両端は中心から扇状に蓋をする

gableRoof / shedRoof（屋根）— 板厚はどこでも同じ

overhang 既定 0.18、thickness 既定 0.12
外側の断面（u-z 平面）
  切妻：(-halfSpan, lowZ) → (0, h) → (halfSpan, lowZ)
  片流れ：(-halfSpan, lowZ) → (halfSpan, h)
内側の断面 = offsetPolyline2D(外側, thickness)     ← 法線方向へ t だけずらす
断面 = 〔外側を進む〕＋〔内側を逆順で戻る〕＝閉じた多角形
両端（軒先）は「鉛直に切る」：高さを t·L/run だけ下げる（L=斜辺長, run=水平長）
   → 斜面上の垂距離が端でも中央でもちょうど t のまま
棟に沿って axis（x か y）へ half だけ押し出す

ポイント：内側の線を 法線方向のオフセットで作るので、 勾配が急でも緩でも 板の薄さはどこでも均一になります。

ramp（スロープ）

手前 (y=-d/2, z=0) が床、奥 (y=+d/2, z=h) が立ち上がり
側面・底面・斜面・背面の6辺を結ぶ
handrail=true なら左右に手すり（高さ railH 既定 0.42）と支柱4本ずつ

windowGrid（窓グリッド）

板の厚み t = d（0.01 以上）。表裏に同じ四角を置き、4隅を結んで厚みを出す
窓の割り付け（facadeWindowGridRects）
  usableW = w − 2·marginX          marginX 既定 0.12w
  usableH = h − sill − head        sill 既定 0.22h / head 既定 0.12h
  cellW = (usableW − gapX·(cols−1)) / cols
  cellH = (usableH − gapZ·(rows−1)) / rows
  窓1枚の大きさ windowW / windowH を指定すると、セル中央に置いて四方を均等に空ける
  → 分割数（rows × cols）と窓1枚の大きさの **両方** が画面上で編集できる

custom（読み込んだ任意形状）

geometry.vertices（点）と edges / loops（辺・面の並び）を、そのまま3D線画へ
この形だけは作成サイトと同じ座標系なので、customPt()（x=左右/y=奥行き/z=高さ）を使う

注意：custom は座標系が他と違うため、必ず専用の点列（customPt） を通します。 L2W に混ぜると、オブジェクトを動かしたときに線だけ取り残されます。

7. 面表示（塗り）の原理

「面表示」をONにすると、線画に加えて 半透明の面が塗られます。 

exportSurfaceTriangles(o)   // o → 三角形の配列（ワールド座標の3点）
   ↓  視点ごとに exportPoint() で画面座標＋奥行きへ
   ↓  3点のどれかが画面外／奥行き不定なら捨てる
   ↓  画面での面積が 0.001 未満なら捨てる（線に潰れた面）
   ↓  奥行き（3点の平均）で降順ソート = 遠い面から描く（ペインター法）
   ↓  不透明度ごとにグループ分け（通常は全部 0.22 で1グループ）
   ↓  オフスクリーンの層へ「不透明」で描く（重なっても濃くならない）
   ↓  面が写った範囲だけを切り出し、1回だけ半透明で合成
   ↓  globalAlpha = surfaceAlpha(o)（既定 0.22）で drawImage

重要：面を1枚ずつ半透明で塗ると、同じオブジェクトの中で面が重なる場所だけ 透明度が積み上がって乗算したように濃くなる（開口の奥の壁、柱の裏、箱の角など）。 そこで「不透明で1枚の層に描いてから、最後に1回だけ半透明で重ねる」方式にしています。 層の中で三角形どうしが重なっても色は濃くならず、どの面も同じ濃さのベタ塗りになります。 オブジェクトが2つ重なる場所は、層が2枚重なるので少しだけ濃くなります（半透明の正しい見え方）。

層を作るときの工夫：

工夫理由
面が写る範囲だけの大きさで層を作る画面全体を毎回クリアすると重い（140オブジェクトで実測1.5倍遅かった）
同じ色は1本のパスへまとめる（400枚ずつ）三角形ごとに fill するとパス生成が増えて重い
パスへ入れる前に三角形の巻き方向をそろえる逆巻きが混ざると nonzero で打ち消し合い、塗りが抜ける（裏表の面が重なる立体で顕著）
塗りと同じ色で 1/拡大率 の太さの縁をなぞる隣り合う三角形の継ぎ目に細い筋が透けるのを防ぐ（画面上で常に1px）

三角形の作り方はアセットごとに専用です（exportSurfaceTriangles の中）。

重要：面は「実際の形の外側を塗らない」ことを優先しています。 凹んだ形（凹窓階層建物など）は、包絡箱ではなく 凹みに沿った多角形を polygonEarClip（耳切り法）で三角形分割します。 重心から扇状に分割すると、凹みをまたいで 形の外へはみ出した尖りが出るためです。

11. つまずきやすい所

  • ra / rb は半分。「幅4m」は ra = 2。w = ra*2 を忘れると線が半分になります。
  • d は必ず −1。d を正にすると −d·z の符号が反転し、上下が逆に伸びます。
  • z はローカル高さ。L2W の中では −d·z として掛かるので、
    アセットの式の中では「実寸の高さ」をそのまま渡してかまいません。
  • 共有辺を二重に描かない。階層建物は面ごとに輪郭を足すと縁が2重線になるため、
    箱の12辺を1回ずつ描いています。
  • 凹んだ形は専用の三角形分割が必要。重心分割は形の外へはみ出します（耳切り法を使う）。
  • 接着パーツは親の変更で作り直す。setOb が子も再生成しますが、
    手で S を触ったときは syncAttachedPart を通してください。
  • 面表示の近似：専用の面関数がまだ無いアセットは包絡箱で塗るため、
    凹みの内部には面が入りません。線画は正確です（新アセットを足すときは
    exportSurfaceTriangles に分岐を1つ足すのが本筋）。

14. 実際の数値で1回とおす（検算の例）

「建物 4×3×5 に付属テント（3×1×1）を付ける」を最後まで計算してみます。 

① 建物の寸法         ra=2, rb=1.5, h=5
② 開口              openingW = 0.56×4 = 2.24
                    openingH = 0.66×5 = 3.3
                    backY    = 1.5 − 0.025 = 1.475
③ 線と面            親は「開口なしの閉じた箱」なので 線 6本 ／ 三角形 12枚
                    （テント付き建物の親は openingEnabled=false で作られる）
④ 付属テントの位置   attachedNormal = 0.5 + 0.008 = 0.508
                    faceY  = −(1.5 + 0.508) = −2.008   （手前へ 2.008 m）
                    z      = 3.6                        （下端）
                    上端   = 3.6 + 1 = 4.6              （建物5mの0.4m下）
⑤ テントの形         edgeZ = h = 1、edgeY = −rb = −0.5 → 直方体
                    板厚 = max(0.04, 0.14×1) = 0.14
⑥ 線と面            子テントは 線 6本 ／ 三角形 12枚
                    → 親子合計で 12本・24枚

確かめ方（開発者ツールのコンソール）： 

const objs = window.cityGridStudioBridge.sceneObjects();
const parent = objs.find(o => o.asset === "building");
const child  = objs.find(o => o.attachment);
[parent.ra * 2, parent.rb * 2, parent.h];   // → [4, 3, 5]
buildingGeometry(parent);                    // → openingW 2.24 / openingH 3.3 / backY 1.475
child.attachment.baseZ;                      // → 3.6（地面からの高さ）
child.lift - 1;                              // → 2.6（ワールドY。地面が −1 なので 3.6m）
assetLines(parent).length;                   // → 6（閉じた箱）
exportSurfaceTriangles(child).length;        // → 12

注意：ワールドの高さは 地面が y = −1 です。 「地面から3.6m」は y = 2.6。資料の「3.6」はすべて 地面からの実寸で、 lift − 1 のような式の結果とは 1 だけずれます。

ポイント：すべての数値が「初期値の表（§6.1）」と「式（§6.2・§6.3）」の 両方から同じ値になることを確かめてあります。片方だけ違えば、式か表が古い証拠です。
