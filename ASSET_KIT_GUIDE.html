ASSET_KIT ガイド — アセットを「1つの記述」から作る

新しいアセットを足すとき、これまでは同じ形を2か所に書く必要があった。

書く場所何のため
asset.js の ASSET_LINE_BUILDERS[kind]線画（線）
engine-render.js の exportSurfaceTriangles()面（塗り・隠線・シルエット判定）

asset-kit.js は、この2つを部品（parts）の一覧1つにまとめる。
部品を書けば、線も面も同じ記述から作られる。片方だけ直して食い違う事故が起きない。

  • 実装：asset-kit.js
  • 部品カタログ：asset-kit-parts.js（窓・扉・室外機・ベンチ・日よけ・車輪・配管・看板。→ §12）
  • 作ったアセット：asset-kit-assets.js
    • 新規：電光看板 lightboxSign、自販機 vendingMachine、店先 shopFront（部品カタログの見本）、
      室外機 outdoorUnit（丸いファン＋ガード＋側面ルーバー＋脚）
    • 既存から移した：コの字壁 uWall・壁付け看板 wallSign（線も面も）、
      屋台 stall・壁付けベランダ balcony・丸椅子 stool・手すり railing（面のみ）
  • 点検：node check-all-assets.js（棚の全カード＝キット製も含む）と bash tests/run.sh tests/kit-assets.js

1. 30秒でわかる例

ASSET_KIT.define(
    "lightboxSign",                                        // 種類の名前（JSONの asset に入る）
    { label: "電光看板", glyph: "▤", w: 1.0, d: 0.36, h: 1.2, accent: "#ff5a7a",
      lightboxFrame: 0.055 },                              // ← 固有値もここに書ける
    (o, K) => {
        const W = Math.abs(2 * o.ra),                       // 幅（画面の寸法がそのまま入る）
            D = Math.abs(2 * o.rb),                         // 奥行き
            H = Math.abs(o.h),                              // 高さ
            frame = K.param(o, "lightboxFrame", 0.055);     // 画面で変えた値 > 初期値
        return [
            K.box(K.roundRectPath(W, D, 0.05, 2), 0.34, H), // 板（丸めた長方形を押し出す）
            K.box(K.rectPath(0.055, 0.055, W / 2, 0), 0.04, H), // 右脚
            K.box(K.rectPath(0.055, 0.055, -W / 2, 0), 0.04, H), // 左脚
        ];
    },
);

これだけで、次が全部そろう。

  • アセット棚に並ぶ（ASSET_LINE_BUILDERS 未登録の種類は自動で「街・パーツ」に入る）
  • 線画が出る（部品の稜線がそのまま線になる）
  • 面が塗られる（奥行きバッファに乗るので、隠線・シルエット判定・面の内側の線の除去が効く）
  • 回転・生成面（k）・接着に追従（座標変換は L2W() に任せるので自動）
  • JSON 保存・読み込み・複製（asset 名と寸法だけ持つので既存の仕組みにそのまま乗る）

2. 座標のきまり

asset.js の既存アセットと同じ。

  • x … 左右（＋が右）
  • y … 奥行き（＋が奥）
  • z … 高さ（＋が上、0 が接地）
  • 原点は部品の中心。o.ra / o.rb / o.h は画面の寸法欄の値なので、そのまま使う。

ワールドへの変換（回転・生成面・接着・傾き）は 必ず K の部品を通すこと。
自分で L2W を呼ばなくてよい。

3. 部品（parts）

書き方できる形
K.box(path, z0, z1)2Dの道筋を z0〜z1 へ押し出した柱・箱
K.sheet(path, z0, z1)上下の面だけ（板・シート。側面の線を出さない）
K.face3([[x,y,z],…])自由な3Dの面（斜めのガラス・屋根・面取り）
K.roundedBox(w, d, h, r)曲面：上下の縁と四隅を丸めた直方体（冷蔵ケースなど）
K.depthBeveledBox(w, d, h, r, {z0, seg})前後方向の4辺だけを丸めた箱。x-zの角を丸め、y軸へ押し出す
K.loft([{path, w}, …])断面を積み上げる（曲面を自分で設計したいとき）
K.cylinder(r, z0, z1, {seg})円柱：脚・ポール・棒・タイヤ（断面は正円の n 角形）
K.revolution(断面, {seg})回転体：球・円錐・脚・植木鉢（断面 [[r, z], …] を z 軸まわりに回す）
K.repeat(本数, fn)同じ形を等間隔に並べる（階段の段・柱・縞）
K.grid(行, 列, fn)格子に並べる（窓・ブロック塀）
K.count(値, 既定, 最小, 最大)本数を整数へ丸めて範囲に収める

穴あけ（ブーリアン差）

K.box(K.rectPath(0.9, 0.7), -0.03, 0.03, {
    axis: "y",                                  // 正面を向いた板（厚みは y）
    holes: [K.rectPath(0.6, 0.4, 0, 1.1)],      // 板の中心から (0, 1.1) に 0.6×0.4 の穴
    holeSides: true,                            // 穴の内側の壁も作る（奥行きが出る）
})

holes は何個でも書ける。外側の道筋の穴の位置に、橋渡し（bridge）を入れて
1本の多角形にしてから三角形分割するので、穴の中は面で埋まらない（＝向こうが透ける）。

円柱（K.cylinder）

K.cylinder(0.18, 0, 1.2, { seg: 20 })                  // 立てた柱（座面・脚・台座）
K.cylinder(0.05, -1.5, 1.5, { seg: 12, axis: "y" })   // 奥へ寝かせた棒（手すり・配管）
K.cylinder(0.3, 0, 0.02, { seg: 24, caps: true })     // 薄い円盤（タイヤの縁）
オプション既定意味
seg20断面の角数（8〜24 くらい。大きいほど滑らか）
axis"z"押し出す向き（"z"＝立てる、"y"＝奥、"x"＝横）。z0, z1 はその向きの範囲
cx / cy0断面の中心（axis に垂直な面内）
capstrue上下の面を出すか。false にすると筒だけ（側面だけ）
verts0側面に足す縦線の本数
  • 円の面は中心から扇状に分割する（既存アセットの円柱と同じ作り）。
  • 線は上下の輪だけ（verts を足すとその本数だけ縦線）。全頂点に縦線を出すと筒が縞になるため。
  • 視線に直角な位置の「シルエットの線」は視線で決まるので、部品の一覧からは作れない。
    そこまで揃えたいアセット（丸椅子など）は lines: false で線を既存のまま残す。

並べる道具（repeat / grid / count）

const n = K.count(o.steps || 6, 6, 2, 24);     // 段数（整数へ丸めて 2〜24 に収める）
K.repeat(n, (i, t) => K.box(K.rectPath(w, sd, 0, cy(i)), 0, z(i)));   // 段を並べる
K.grid(3, 4, (r, c, u, v) => K.box(K.rectPath(0.4, 0.3, x(c), y(r)), 0, 1)); // 窓を格子に
  • t / u / v は 0→1 の進み具合（1個だけなら 0）。段の高さ・柱の位置をここで決める。
  • 返すのは部品でも線でもよい。既存アセットの「線の選び方」を変えずに、繰り返しだけを畳める。 
// 既存の線画（asset.js）でも同じ道具が使える
out.push(...K.repeat(n, (i) => lineA(o, [[x, y0(i), z0], [x, y0(i), z]], a, 0.9)));

回転体（K.revolution）

K.revolution([[0.5, 0], [0, 1]], { seg: 12 })            // 円錐（先端が軸上なら上面は出さない）
K.revolution([[0, 0], [0.5, 0.5], [0, 1]], { seg: 16, rings: [1] })  // 球（赤道の線を1本足す）

断面は [[半径, 高さ], …] を下から上へ。r = 0 の点は軸上（頂点）として扱い、そこには面を出さない。
rings に断面の番号を入れると、その高さの輪の線を足せる（球の赤道・壺の肩など）。

押し出す向き（axis）

axis道筋の2D座標押し出す向き使いどころ
"z"（既定）x, y上（z）箱・柱・接地する部品
"y"x, z奥（y）正面を向いた板・壁・窓枠
"x"y, z横（x）横向きの板

道筋の点は axis に垂直な面内の座標になる（"y" なら [x, z]）。
最後の2引数 z0, z1 は押し出す範囲（axis に沿った座標）。

文字（線のフォント）

...K.textPart("FROZEN FRESHNESS", {
    face: "front",   // front / back / left / right / top
    plane: -0.42,    // その面の位置（front なら y）
    u: 0, v: 1.5,    // 面内の中心（front の u は x、v は z）
    height: 0.12,    // 文字の高さ（m）
    stroke: 0.018,   // 線の太さ（m）
    proud: 0.012,    // 面から手前へ出す量（板に隠されないように）
})

英大文字・数字・- . , : / + ! ? & ( ) ' * と空白に対応。文字は「細い板（面）」として
出るので、縁が線になり、面の内側の線の判定にも乗る（＝板に貼っても消えない）。
日本語は未対応（必要になったら GLYPHS に足すか、線の組み合わせで描く）。

部品には任意で次を付けられる。 

K.box(path, 0, 1, { color: "#ff5a7a", width: 3, noTop: true, noBottom: true, noSides: true })
フィールド意味
color / widthその部品の線の色・太さ（省略時はアセットの色・太さ）
noTop / noBottomその面（と、その輪の線）を出さない
noSides側面を出さない（上下だけ）
sheetnoSides ＋ 縦の辺の線も出さない

道筋（path）を作る道具

K.rectPath(w, d)                       // 長方形
K.roundRectPath(w, d, r, seg)          // 角を丸めた長方形（seg=1 で面取り）
K.circlePath(r, n)                     // 円（n角形）
K.offsetPath(path, dx, dy)             // 平行移動
K.scalePath(path, sx, sy)              // 伸縮
K.rotatePath(path, deg)                // 回転（度）

道筋は [[x, y], …] の配列で、自動で閉じる（最後の点から最初へ戻る線が出る）。
凹んだ形（L字・コの字）も書ける。面は耳切りで三角形分割される。

4. 値の持ち方（画面から変えられるようにする）

K.param(o, "lightboxPanelBottom", 0.34)
  1. o.lightboxPanelBottom（画面・JSONで変えた値）
  2. ASSETS[kind].lightboxPanelBottom（define の meta に書いた初期値）
  3. 第3引数（最後の決め打ち）

の順で読む。つまり meta に書いておけば、asset-controller.js を触らなくても初期値を持つ。
画面の数値欄・ハンドルを付けたいときだけ、asset-controller.js の newAsset() と
engine-gizmo.js の specialGizmo() に1か所ずつ足す（既存アセットと同じやり方）。

5. 線と面はどう描かれるか（既存の描画ルールに乗る）

  • 線：部品の上下の輪と縦の辺が、1本ずつの折れ線として出る。
  • 面：上下の面＋側面が三角形で出る → 奥行きバッファに入り、隠線判定の対象になる。
  • そのため、面の内側を通る線は自動で消え、外形の線は残る（CITY_GRID_STUDIO.md 5Z-19）。
    キット側で「消す線」を選ぶ必要はない。
  • 面の段差（板の上に一回り小さい板を重ねる等）を作ると、その縁は外形として線が残る。
    写真のような「フレーム＋印刷面」は、この段差で表現するのが簡単。

6. 既存アセットをキットへ移す（replace）

ASSET_KIT.define("uWall", { label: "コの字壁" }, (o, K) => [
    K.box(profile, -hd, hd, { axis: "y" }),
], { replace: true });                 // 線も面もキットの記述から作る

ASSET_KIT.define("stall", { label: "屋台" }, (o, K) => [...],
    { replace: true, lines: false });  // 面だけキット。線は今の描き方を残す
  • replace: true … 既にあるアセットを置き換える。ASSETS の初期値（寸法・固有値）は既存を優先するので、
    棚の見た目・既定値・保存済み JSON は変わらない。
  • lines: false … 線は ASSET_LINE_BUILDERS の今の関数をそのまま使い、面だけキットから作る。
    既存アセットは「描かない線」を手で選んでいる（内側の稜線・床の縁など）ので、
    線まで置き換えると面OFF（線画のみ）の見た目が変わる。形の計算（uWallGeometry など）を
    共有していれば、面だけ移しても形は食い違わない。
  • 移したら、面ONと面OFFの両方を画素で比べる（チェック手順参照）。差が出たら理由を確かめてから採る。

7. 新しいアセットを足す手順

  1. asset-kit-assets.js に ASSET_KIT.define(...) を1つ書く
  2. bash build.sh（構文チェック＋単体HTML生成）
  3. bash tests/run.sh tests/kit-assets.js（キット製アセットの点検）
  4. node check-all-assets.js（棚の全アセットの点検。新しい種類も自動で対象になる）
  5. アプリで棚から置いて、拡大・回転・面ON/OFFを確認

ASSET_KIT.define の第2引数に書ける w / d / h はメートル。既存アセットと同じ目安
（人 1.7m、店の看板 2m、屋台 2.4m など）。

8. 例：冷凍ショーケース（斜めのガラス戸）

face3 は「自由な3Dの面」なので、斜めのガラスもそのまま書ける。 

ASSET_KIT.define(
    "freezerCase",
    { label: "冷凍ショーケース", glyph: "▯", w: 1.6, d: 0.9, h: 1.15, accent: "#f4f6f8" },
    (o, K) => {
        const W = Math.abs(2 * o.ra), D = Math.abs(2 * o.rb), H = Math.abs(o.h),
            bodyH = H * 0.62,                 // 胴（下の箱）
            lidH = H - bodyH,                 // ガラスの傾き分の高さ
            back = D / 2, front = -D / 2;
        return [
            K.box(K.rectPath(W, D), 0, bodyH),                      // 胴
            K.box(K.rectPath(W, 0.06, 0, front + 0.03), bodyH, H),  // 手前の見返し
            // 斜めのガラス戸（前が低く、奥が高い）
            K.face3([
                [-W / 2, front + 0.08, bodyH],
                [W / 2, front + 0.08, bodyH],
                [W / 2, back, bodyH + lidH],
                [-W / 2, back, bodyH + lidH],
            ]),
        ];
    },
);

ガラスは「面」があるので、その上を横切る線（中に入れた商品の線など）は
面の内側の線として消える。見せたい線は段差か別部品にして、外形へ出す。

9. 例：自販機（前後辺のベベルと穴あけ。中の寸法は「割合」で持つ）

asset-kit-assets.js の vendingMachine がそのまま動く作例（棚に入っています）。 

ASSET_KIT.define("vendingMachine", { label: "自販機", w: 1.0, d: 0.75, h: 1.83 }, (o, K) => {
    const W = Math.abs(2 * o.ra), D = Math.abs(2 * o.rb), H = Math.abs(o.h),
        front = -D / 2,
        panel = (pw, ph, cz, holes, cx = 0) =>            // 前面の板（穴あき）
            K.box(K.rectPath(pw, ph, cx, cz), front - 0.015, front + 0.05,
                  { axis: "y", holes, holeSides: true });
    return [
        K.depthBeveledBox(W, D, H, K.param(o, "vmDepthBevel", 0.03), {seg: 3}), // 前後方向の4辺だけ丸める
        panel(W * 0.78, H * 0.44, H * 0.54, [K.rectPath(W * 0.62, H * 0.35, 0, H * 0.54)]), // 商品の窓（穴）
    ];
});

// 幅・高さを変えると、窓・看板・小銭入れ・取り出し口も一緒に伸び縮みする。
// 中の寸法は meta に「割合（0〜1）」で持たせ、W・H へ掛ける。

窓の穴からは向こうが透け、中に薄い棚を入れると奥行きが出る。看板の板は無地（文字は入れていない）。

10. できないこと（今の範囲）

  • 自由な曲面（球・ラッパ状）は無い。roundedBox（上下の縁＋四隅）と loft（断面の積み上げ）まで。
    球・円錐は既存アセットの機能として残っている。
  • ブーリアンは「穴あけ」だけ（外側−穴）。部品どうしの合体・交差は無い。
    重なりは「重ねて置く」で表現する（面の段差になるので線は自然に出る）。
  • 日本語の文字は無い（英大文字・数字・記号のみ）。
  • テクスチャ（写真の貼り付け）は無い。
  • 凹んだ面は耳切り分割。極端に自己交差した道筋を渡すと面が崩れるので、
    道筋は交差しないようにする。

11. 参考：内部の決まり

  • ASSET_KIT.define(kind, meta, build) は registerAsset() を呼び、build(o, K) の戻り（部品配列）から
    線を作る。面は engine-render.js の exportSurfaceTriangles() が
    window.assetKitTriangles(o) を通して同じ部品配列から作る（形の記述は1か所）。
  • 面のキャッシュ（surfaceTriCache）はオブジェクト全体の JSON をキーにしているので、
    固有値（lightboxFrame など）を変えても面は作り直される。
  • 三角形の向き（表裏）は描画では問わない（奥行きだけで判定するため）。

12. 部品カタログ（asset-kit-parts.js）

よく使う小物は部品として登録してあり、アセットはそれを並べるだけで作れる。 

...K.part("window", { w: 0.9, h: 0.6, at: [-0.6, 0, 1.1] })
...K.part("door",   { w: 0.55, h: 1.0, at: [0.3, 0, 0.5] })
...K.part("signBoard", { text: "", at: [0, -0.1, 2.1] })   // 無地の看板
部品できる形主な指定
window枠（穴あき）＋ガラス＋縦桟w h frame d glass mullion
door枠＋扉板＋取っ手w h frame d handle
acUnit室外機（本体＋ファン＋十字＋ガラリ＋脚）w h d
bench座面＋背もたれ＋脚w h d t back
awning日よけ（斜めの幕＋垂れ＋腕）w d drop t z
wheelタイヤ＋ハブ＋スポークr t
pipeRun管＋フランジ2枚len r axis
signBoard板＋文字（text: "" なら無地の板）w h t text textScale
pentaPrism五角形の立体（前の面→斜め→上面→背面を左右へ押し出した塊）w L frontY backY edgeH roofH slant
tireタイヤ1本（左右向きの円柱。地面に接する高さへ自動で置く）r t x axleY seg

どの部品も at: [x, y, z] で置ける。部品は原点中心・正面 −Yで作ってあるので、
壁（axis:"y" の板）に貼るだけなら at の y を少し手前へずらす。

    ...K.repeat(3, (i) => K.box(K.rectPath(0.36, 0.02), -0.03, -0.02, { axis: "y" })),
]);

室外機のファン位置（ouFanX）

ouFanX はファン中心の左右位置を m（実寸）で持つ。幅 W を変えても値はそのままなので、
胴を広げても狭めても円は動かない。動かせる範囲は ±(W/2 − fanR)（円が胴からはみ出さない所）で、
これを超える位置は自動で内側へ寄る。3Dビューでは円の右外側に出る左右矢印のハンドルで横移動だけできる。

形を決める計算は outdoorUnitGeometry(o)（engine-gizmo.js）に集約してあり、
線画（outdoorUnit）とハンドルは同じ値を使う。寸法を足すときはこの関数へ入れ、
asset-kit-assets.js 側では受け取るだけにする。

新規アセットの共通登録・設定・画面ハンドル（2026-11-03）

従来の ASSET_KIT.define(kind, meta, build) の meta に group と controls を追加できる。既存アセットの専用UI・線画は変更せず、新方式で宣言したものだけ共通の設定欄を生成する。 

ASSET_KIT.define("example", {
    label: "例", glyph: "▤", w: 1.4, d: 1.1, h: 2,
    group: "building", // primitive / building / buildingParts / street / person / vehicle
    controls: [{
        key: "postLength", label: "ポールの長さ", type: "number",
        default: 0.4, min: 0.1, max: 1.2, step: 0.05, unit: "m",
        // アセットの形に応じて基準点を渡す。増加方向は z（高さ）。
        handle: (o, v) => ASSET_KIT.axisHandle("z", [0, 0, o.h], v),
    }, { key: "withCap", label: "頭部", type: "boolean", default: true }],
}, (o, K) => [
    K.box(K.rectPath(1, 1), 0, o.h),
    K.box(K.rectPath(.12, .12), o.h, o.h + K.param(o, "postLength", .4)),
]);
  • controls は number と boolean に対応し、数値の min・max は数値または (o) => 数値。入力とドラッグはUndo/Redoに対応し、値はオブジェクトJSONに保存される。
  • 数値の handle は (o, value) => ({anchor, sample, probe, fallback, color})。最初の3つはローカル3D座標で、sample が現在のつまみ、probe は値を1増やす方向の点。ASSET_KIT.axisHandle(axis, anchor, value, sign) は軸方向に動く定番形。視線方向へ重なったときは画面上の代替方向で操作する。複雑な制約や左右対称の編集は従来の専用ギズモを使う。
  • 新方式では種類名を高さハンドルのリストへ追加せず、通常の立体に上下面ハンドルを表示する。専用ハンドルを持つ例外は登録情報の heightControl: "custom" で指定する。ポール付きアセットではポールの長さの画面ハンドルも定義する。
  • controls を宣言した新方式は、線・面の部品頂点から選択範囲を作る（geometryBounds:false で従来方式を明示可能）。既存アセットの境界は一括変更しない。
  • 棚グループは従来の明示リストが優先。リストにない新しい登録は group を利用し、未指定なら街パーツへ入る。静的登録は asset-kit-assets.js の中で、棚が作られる前に行う。
  • テスト用の登録をアプリへ恒久追加せず tests/asset-registration.js から挿入して、登録・部品の外接範囲・UI・保存値・Undo/Redo・高さ／ポールハンドルの実ドラッグを検査する。

蛇腹の配置とトラック型

ASSET_KIT.accordionBands(height, count, duty, depth) は、全高を保ちながら段と溝の範囲を交互に返す。count は段数（1〜48）、duty は段の厚さの割合、depth は断面の内側への引っ込み量。ASSET_KIT.accordionLoft(profile, options) は、profile(z, inset) が返す一定頂点数の断面から部品を作る。具体的なアセットは断面を用意し、線と面を同じリングから生成する。隅切りの開口はその高さでリングを分割し、開口と元の縁も維持する。

アプリ上では対応する既存の直方体・ベベル直方体・隅切り直方体・三角柱・円を押し出した円柱・トラック型を選び、「アセット設定」の「蛇腹」をONにする。段数、段の厚さ（割合）、溝の深さを調整できる。長方形／直方体では角丸の半径、分割数と4角それぞれのON/OFFを指定できる。平面は先に「立体化」するか高さを付ける。三角柱は既存プリミティブと同じ、横から見て三角形の向き。

「トラック型」は中央の長方形と両端の半円。左パネルと画面の専用ハンドルで直線部分の長さと幅を別々に調整でき、幅を変えても直線部分の長さは維持する。面ハンドルや「立体化」で高さを付けられる。

自販機・信号機の前後方向ベベル

自販機の胴、車両用・歩行者用信号機の灯器は、前後に沿う4辺だけを丸める。画面の「前後辺のベベル」ハンドルまたは数値で半径を調整でき、0では直角に戻る。灯・ひさしやポール、自販機の窓・棚・取り出し口は別部品のまま。

蛇腹の画面操作

蛇腹をONにした立体の柱を選択すると、「蛇腹の段数」「段の厚さ（割合）」「溝の深さ」のハンドルをドラッグできる。段の厚さは長さではなく段と溝の周期に対する割合。段数は整数で、全高はそのまま。既存の数値欄も使える。蛇腹OFF時や高さのない平面ではハンドルは表示されない。

14. ベジェの共通編集とケーブル部品

3点の二次ベジェを将来の紐・ケーブル・装飾に使える。quadraticEditor が保存用の数値項目（始点・曲げ点・終点のXYZ）、画面ハンドル、制御点の破線表示、幅ハンドル用のX座標スケーリングをまとめる。高さZの値はオブジェクトの h からの差。points(o) は高さを反映済みのローカル3D制御点、curve(o,t) は曲線上の点（0〜1）を返す。 

const wire = ASSET_KIT.quadraticEditor('wire', [
  [-1.5, 0, 0], [0, 0, -0.45], [1.5, 0, 0]
]);
ASSET_KIT.define('exampleWire', {
  label: 'ケーブル例', group: 'street', w: 3, d: .3, h: 1.5,
  bezierEditor: wire, constrainEdit: wire.constrainWidth,
  controls: [...wire.controls]
}, (o, K) => [K.quadraticTube(o, wire.points(o), .02, {steps: 24, sides: 10})]);
  • キーは例なら wireStartX〜wireEndZ。各値は通常のJSON保存・Undo/Redo対象。
  • K.quadraticPoint(points, t) は3点の二次ベジェ補間。K.quadraticTube(o, points, radius, opts) は円断面の面と、カメラに応じた外輪郭を同時に作る。steps は4〜96、sides は6〜20に制限。全制御点が一致した場合は潰れた線のみを返す。
  • 輪郭は視点依存なので、配置したい位置の制御点を先に移動してから quadraticTube を生成する。任意メッシュを作成後に K.moveParts で移動する使い方には対応しない。
  • 提灯の紐は同じ quadraticEditor('lantern') を使用し、以前のJSONキーを維持する。ベジェケーブルは quadraticEditor('cable') と円断面を使用する。
  • 参考資料：ユーザーが添付したBlenderアドオン Cablerator（Sergey Kritskiy、GPL-3.0-or-later）の端点・曲線・太さを分けて編集する考え方を参照。Blender用Pythonコードはアプリに組み込まず、上記Kitは独自に実装した。

店先パーツの単体化

従来の shopFront は旧保存互換のため定義を残し、棚から非表示にした。カタログの awning と window を使う独立アセットは shopAwning / shopWindow。通常の寸法ハンドルに追従し、窓の中央桟は mullion:true で幅が狭くても残せる。日よけ部品には valanceH、armBelow、armAbove の任意値を追加しており、省略時は従来の固定値を使う。

スライダーと動的な外接範囲

登録型 controls の type:'range' は数値項目と同様に min / max / step / default を持ち、設定パネルにスライダーと現在値を表示する。handle があればキャンバス上でもドラッグできる。段ボール streetParcel の parcelOpen が例。開いたふたのように基準寸法の外に出る部分は geometryBounds:true として、実際の面と線から範囲を計算する。

geometryBounds は真偽値のほか、オブジェクトを受け取る関数も使用可能。手すりは実形状を使い、以前の画素基準との検証時だけ旧範囲を使う。円形の縦棒は streetRoundPart の実面と輪郭を線画・面で共通にする。

四角椅子の squareLegLength は座面・台座の厚みを保ち、中央の支柱の長さと全高を連動して変更する。

鉢・四角椅子・階段2・タンスの再調整

streetPlantBox は葉を持たない中空の四角鉢で、h が鉢そのものの高さ。squareStool は ra/rb を座面の半幅／半奥行きに使い、座面厚、支柱の半径・長さ、台座の高さ・半径を別々に保持する。足が座面より大きい場合も実形状の範囲を使う。pictureStairs は左右の脇枠の幅と、斜面からの追加高さを共通の寸法として持つ。

shopWardrobe と shopWardrobe2 は共通生成処理から、外側の板・水平棚板・縦仕切り・後退した奥面を作る。wardrobeRows は上側または全体の段数、wardrobeSplit は上側の高さ割合（15〜85%）、wardrobeBoard と wardrobeRecess は実寸。2種類とも前面を実際に開口させるため、手前に全体を覆う箱を置かない。開口の奥行き上限は板厚と本体奥行きから決まり、端部まで押しても範囲外へ出ない。

片側車止め guardPoleHalf は新規配置から外したが、すでに保存されたシーンの読込互換のため登録を残す。

ベベル線画の共通ルール

今後追加・修正するベベルは、ベベル直方体と同じ線画方式を標準とする。対象軸に垂直な断面で beveledBoxFootprint を使い、上下（押し出し両端）の輪郭は実際の多角形に沿わせる。縦の稜線は全てを無条件に描かず、beveledEdgeMark で角ごとに候補として登録し、面ONではシルエット、線のみでは各角の代表1本を用いる。複数部品は部品ごとにグループを分け、配列でもコピーごとに候補が競合しないようにする。ASSET_KIT の seamMarks は部品の partEdges と同じ順番で候補の印を指定できる。棚2はこの使い方の実例。実面・隠線・出力と、異なるカメラ方向を合わせて検査する。

画面用ひさし部品 screenHood

モニターの上下左右を囲む、前後に開口した枠。上側のつばが正面に張り出し、左右側面の折れ点から下は短い一定の出幅になる。左右の折れ点は同じ高さで連動する。四隅の前後方向の辺は、ベベル直方体と同じ4分割の輪郭点・角ごとのseam選択で線画化する。 

// 背面を y=0 にするには、at の y を -(frameDepth + brimLength)/2 にする。
const hood = K.part('screenHood', {
    w: 1.1, h: 0.8, frameDepth: 0.10, brimLength: 0.30, t: 0.04,
    knee: 0.44, bevel: 0.10,
    at: [0, -0.2, 0], color: '#30383d', width: 1,
});

埋め込みひさしを持つアセットは、同じパラメータ読取関数を形状ビルダーと K.hoodControls(prefix, read, limits) の両方で共有し、傾き・枠の長さ・つばの長さ・厚さをキャンバス編集可能にする。監視カメラはこの共通コントロール生成関数を使用する。

  • w／h は背面の外寸。frameDepth は背面から折れ点以下の枠前面までの出幅、brimLength は枠前面から上端までの追加張り出し（0以上）。枠とつばは独立して編集できる。背面から上端までの合計は両者の和。旧 length だけを指定した部品や旧保存は、互換のため枠を合計の1/4、追加つばを3/4として再現する。
  • knee は背面の下端から測る左右共通の折れ点の高さ（m）。上端から折れ点へは直線、折れ点から下端へは出幅一定。角の丸みと板厚のため上下端には制限がある。
  • t は枠の厚さ、bevel は上下4角に共通する面取り量（m）。at、color、width は部品位置と線スタイル。前後の輪郭と三角面は同じメッシュから作る。
  • 以前の3面版の angle は使用しない。既存の信号機の筒型ひさしはこの部品に置換しない。
  • keepAnchorPatch は、独立オブジェクトの寸法変更時に背面などの取付点を固定する共通補助。接着オブジェクトは対象外。

タイル舗道の縁石

streetPavement は pavementCurbEnabled でタイル外側四辺の縁石をON/OFFする。pavementCurbWidth は外側への幅、pavementCurbHeight は舗道上面からの高さ、pavementCurbBevel は外側四隅のベベル量（最大は縁石幅）。3項目を画面ハンドルと数値で編集できる。タイル面は覆わず、各辺にタイル間隔の目地を描く。外角の点列・線候補はベベル直方体と同じ方式。旧データやOFF時は従来どおり。

部品を重ねる・横に並べる

K.repeatParts(parts, {axis:'z', spacing:height, count:3, group:'crate'}) は部品群をローカルX/Y/Zの指定軸に等間隔で配置する。元を含む個数・符号付き間隔で、部品・メッシュ・面の移動を K.moveParts に委ねる。ベベルの線候補はコピーごとに独立したキーにする。同じアセット内で複数の反復群を作る場合は group を別名にする。飲料コンテナの縦積みで使用する。

オブジェクト全体の編集可能な繰り返しには、別途共通の配列機能（arrayModifierSpec）を使う。こちらはワールド軸・中心間隔で、個数・間隔・方向を選択中のオブジェクト欄から編集できる。

編集画面上部の共通スライダー

studio-canvas-controls.js は菱形ハンドルと登録controlから、メインバー直下に横並びのスライダーを共通生成する。移動・回転は対象外。登録controlの type:"range" と canvasSlider:true も表示対象。白い面ハンドルの寸法スライダーには既存の facePatch 等を再利用し、片側編集の挙動を揃える。条件付き項目、寸法制約、ロック、Undo/Redoと保存に連動する。左端の接地・リセットは固定、スライダー部分だけ横スクロールする。

リセットは asset-controller.js の初期定義を使って形状を戻し、位置・向き・線色・配列・グループなどを保持する。アセット棚と正投影操作バーは描画領域の外にあり、領域サイズの変更は ResizeObserver でキャンバスへ反映する。新しい登録型アセットは既存controlの定義を利用できる。

建物の扉と開口奥壁

扉ONの建物では buildingDoorOpening の奥壁座標を扉面に使い、buildingDoorLines の線はその手前2mmに置く。面生成時は元の奥壁面を扉面で置き換える。既存奥壁ハンドルと上部の「開口の凹み」は同じ位置を編集する。直線建物の内部 openingBack は符号付き座標を維持し、UIでは正面からの距離に変換する。隅切り建物は従来の奥行き値を使う。扉ON時の未保存奥壁位置は固定して視点変更で動かないようにする。扉OFFでは従来の奥壁に戻る。

浅い凹みでも建物の縁線を正確に遮蔽するため、扉ONの建物線は onFace・preciseTubeEdge と現在の tubeContourView を持つ。扉OFF時の既存表示は変更しない。検証は5建物の奥行・3種類の扉・保存／操作、0.15mの凹みの画面・出力における独立レイ判定、および扉OFF時の旧版との画素比較を含む。

電車の内装

train グループに連続座面・区切り座面の長椅子と1人掛け、つり革、縦ポール、横手すり、窓付き壁、車内ドアを ASSET_KIT.define で登録する。9種類はいずれも線と面を同じ部品から生成し、寸法・生成面・回転・保存に従う。区切り席やつり革は個数を共通スライダーで変更し、ポールの長さは専用の画面ハンドルも持つ。

つり革と窓・扉の縁は、外周と内周を対応させた環状メッシュで構築し、穴の中を面で塞がない。稜線は輪郭だけを生成して、面の分割線を出さない。窓付き壁と扉の窓は透明面ではなく開口。扉の開き幅に応じて見える扉幅を縮め、中央を開く。

曲線椅子と一括配置

区切り1人掛け trainDividedSeat はY-Z断面を横方向へ押し出した連続シェル。座面のくぼみから背もたれへ曲線状に立ち上げ、内外輪郭と前後端だけを描き、面分割による不要な横線は描かない。区切り長椅子も同じ断面で席を並べる。電車椅子の曲面は不要な輪郭候補を省き、面と主要な外形・区切り線を保つ。寸法や座面高さに対して断面が追従する。

asset-controller.js の placeTrainPreset は独立した通常オブジェクトを作ってからまとめて線を追加する。2種類のボタンは電車棚先頭のみ表示され、既存アセットの一覧には含めない。1操作分の履歴としてUndo/Redoし、既存シーンや生成面設定は保持する。車内全体の位置・向きはカメラ方向に対して決定し、地面上に生成する。

席数の編集では constrainEdit が従来の総幅／席数から1席幅を求め、中心を変えずに新しい総幅を計算する。明示的に幅も渡された場合は上書きしない。座席の隙間から見える支えの極短線には preciseTinyGaps を指定し、その線のみ細かいレイ判定と短い可視点の描画を行う。

電車ドア窓の左右連動

trainSlidingDoor は trainDoorWindowWidth と trainDoorWindowHeight を一組の共通寸法として持ち、左右両方の窓の実開口・枠へ使用する。菱形ハンドルは左窓を操作し、上部スライダーと設定欄からも編集可能。doorGeom で寸法の上限・各扉の位置・開口形状を共通計算する。扉が狭い場合は表示寸法だけを制限し、保存値を壊さない。値がない旧データは以前の leaf*.64 と h*.48 を使用する。

電車窓・扉窓の縁の線画

窓付き壁と左右の扉窓は beveledBoxFootprint と同じ4分割の外周を開口部と枠で共有する。枠内周は枠幅に合わせて角半径を減らし、頂点を対応させて環状メッシュを作る。接する壁と枠の外周後端は同じ線を重複生成しない。開口・枠外側・枠内側の奥行き線には、それぞれ beveledEdgeMark による独立した角の輪郭候補を付ける。非常に小さい窓は輪郭生成時だけ比例拡大してから元に戻し、輪郭の最小寸法で開口が膨らむことを防ぐ。つり革の輪は変更しない。

金網フェンス（chainFence）

chainFence は上角に半径 1.2 * d の90°曲げを持つパイプ外枠と、面を持たない線のみのひし形金網（meshTriangles: []）を返す。直線長 fenceStraight や全体幅 ra・高さ h を変えても角の曲げ半径は fenceDiameter のみから決まり変化しない。ひし形金網は上枠内縁中央を基準に傾き ±1・間隔 fenceMeshPitch の直線群を枠の内側輪郭（上角の内側円弧を含む）で解析的にクリップして生成するため、伸縮時は網目が伸び縮みせず本数が増減する。fenceCount（横に並べる数、画面ハンドル付き）と fenceGap（並べる間隔）に応じ、1枚分の外寸幅 L + 2*b + d に間隔を加えたピッチで横方向へ並べ、各パネルの実座標でパイプの輪郭とリング可視性を計算する。fenceBottomBar（既定ON）がONのときは指定された高さ fenceBottomHeight（下パイプの高さ、画面ハンドル付き）で左右支柱との交線（Steinmetz曲線）により下横パイプをT字接合し、支柱の内側縦線を交差区間の上下に分割して脚を残しつつ、網目下端を下パイプ上縁（zBot + r）へ追従させる。
